# Trading Coach v0.1 产品需求文档（PRD）

- 版本：v0.1（设计定稿，未写代码）
- 日期：2026-08-04
- 状态：待用户拍板 §11 的五个开放问题后进入实现
- 定位：Trading OS 的第二条腿，研究交易者本人
- 覆盖范围：**双市场**（A股 + MT5 外汇/期货）

> **v0.1 内部修订记录**：初稿基于「用户只做 A股」的假设，建议删除原方案的外汇字段。该假设错误，用户同时在 MT5 交易外汇/期货（`backend/mt5_export.py` 已于 2026-08-04 交付）。已修订 §1、§3.4、§5、§9、§11、§12。修订后的核心变化：数据层增加 `market_type` 分区键，Roadmap 拆为 A/B 双线，MT5 历史导入成为最高优先级动作。

## 0. 一句话定义

Trading Coach 是一个**执行质量测量系统**。它不产生交易观点，只回答一个问题：

> 我事前想做的，和我事后做的，差多少？差在哪？

**它不是**交易分析工具，**也不是**心理咨询。它测量「认知 → 行为」这一段的转化损耗。

覆盖两个市场：A股（研投系统已覆盖研究侧）与 MT5 外汇/期货（研投系统不覆盖，仅做执行侧测量）。

## 1. 立项前的现状核查（2026-08-04 实测）

任何设计都要先对齐事实。查询 `backend/database/vibe_research.db` 结果：

| 事实 | 数值 | 对设计的约束 |
|---|---|---|
| `trade_journal` 表已存在 | 121 行 | **不新建表**，改造既有表 |
| 其中真实人工交易 | **0 条** | 所有 AI 分析层必须延后 |
| `rec_type` 分布 | signal 121 / trade 0 | 现有内容是系统信号，非交易记录 |
| `judge_result` | right 63 / wrong 58 | 信号准确率 52%，接近随机 |
| `exec_result` | 空 81 / **missed 40** | 执行层数据**已经在记了**，但分母不清 |
| `action` | 买 121 / **卖 0** | 卖出侧结构性空白 |
| `pnl` | 全 NULL | 无结果数据，无法做盈亏归因 |
| `research_decision_log` | 3 条，全 WAIT/NO TRADE | 决策日志也未闭环 |
| 数据跨度 | 2026-07-20 ~ 08-03，7 个交易日 | 样本积累刚起步 |
| **MT5 账户** | 用户另在 MT5 做外汇/期货，`mt5_export.py` 已交付 | **存在可导出的真实历史成交** |

**第一结论**：A股侧当前瓶颈是采集，不是分析。任何在 0 条 A股真实交易上构建的「行为模式识别」都是伪精确。

**第二结论（关键）**：交易者是**双市场**的。A股侧真实成交为 0，但 MT5 侧存在历史成交且可通过 `mt5_export.py` 批量导出。这意味着冷启动路径不是「从零积累」，而是「先导入 MT5 历史，A股侧同步开始记录」。两侧的分析成熟度会长期不对称，设计必须显式支持这种不对称。

## 2. 定位与边界

### 2.1 与 Trading OS 的关系

```
                    Trading OS
                         |
         ┌───────────────┴───────────────┐
         │                               │
  Research Intelligence            Trading Coach
   （研究市场）                     （研究自己）
         │                               │
  市场什么状态？                   我事前计划是什么？
  钱在哪个板块？                   我实际做了什么？
  风险预算多少？                   两者差在哪？
         │                               │
    输出：候选 + 配置              输出：执行质量报告
         │                               │
         └──────────► 人 ◄───────────────┘
                   （唯一决策者）
```

关键：两条腿的输出**都只汇入人**，彼此不直接连线。

### 2.2 硬边界（红线，不可协商）

| Coach 不做 | 原因 |
|---|---|
| 不给买卖建议 | 一旦给，就退化成「听 AI 交易」，与系统哲学冲突 |
| 不修改任何系统参数 | 前 100 笔样本内，Coach 的任何结论都不足以调整 Layer1/评分/风险预算 |
| 不接入 CIO 层 | 见 §2.3，这是本次对原方案最强烈的反对项 |
| 不做情绪自评打分 | 见 §4.3，事后情绪自评是噪声 |
| 不做实时盘中提示 | 会变成第二个信号源，污染人的判断 |

### 2.3 对「CIO 层结合交易者状态」的明确反对

原方案 §6 提出：CIO 发现「黄金趋势强 + 交易者过去 5 次追涨失败 → 建议暂停追涨」。

**三点反对：**

1. **自相矛盾**。方案 §2 刚立了「Coach 不参与交易决策」，§6 就把 Coach 的输出接进了决策链。二者只能留一个。
2. **样本不足以支撑**。5 次样本推不出任何行为规律，用它调节仓位属于拟合噪声。按用户 2026-08-01 定的 Decision Log 闭环门槛（样本≥20 + 覆盖≥3个月 + 含不同市场状态），5 次连门槛的四分之一都不到。
3. **反馈环污染**。Coach 一旦影响系统输出，Coach 测量的就不再是「人的执行质量」，而是「人 + 系统耦合后的行为」，测量对象被自己的测量行为改变，后续所有归因失效。

**结论**：TIP（Trader Intelligence Protocol）可以立，但只输出到人类可读报告。接入 CIO 的时机最早为累计 100 笔真实交易之后，且需单独立项评审。

## 3. 数据层设计

### 3.1 核心决策：改造，不新建

原方案要新建 `trade_journal`，但该表已存在且已有 `exec_result` 字段并积累了 40 条 `missed` 标记。同时用户 2026-08-01 已收口：**Trade Log 须从 Decision Log 继承，不独立设计**。

因此数据层采用三层继承结构：

```
research_decision_log  （事前：我打算做什么）
        │  decision_id
        ↓
trade_journal          （信号 + 执行标记，已存在）
        │  rec_type='signal' → 系统给了什么
        │  exec_result       → 我执行了没有
        ↓
trade_execution        （事后：我实际做了什么）  ← 唯一新增表
```

### 3.2 立即可做的零成本改造（Phase 0）

**改造 A：`exec_result` 三态化**

当前 81 条空值语义不明，既可能是「执行了」也可能是「忘了标」。改为强制三态：

| 值 | 含义 |
|---|---|
| `executed` | 我买了 |
| `missed` | 看到了，没买（踏空/犹豫/没敢） |
| `rejected` | 看到了，主动否决（有明确理由） |
| `unseen` | 当天没看到这条信号 |

`missed` 与 `rejected` 的区分是本模块的第一个真实洞察点。踏空是执行问题，主动否决是判断行为，两者混在一起就什么都测不出来。

**改造 B：补卖出侧**

`action` 当前 121 条全是「买」。A股实际亏损主要发生在卖出环节（该止损不止、盈利过早了结）。Coach v0.1 的第一优先级是补齐卖出记录，优先级高于任何心理字段。

### 3.3 新增表 `trade_execution`（唯一新表）

设计原则：**单笔填写时间 ≤ 90 秒**。超过这个阈值，记录行为在 3 周内必然中断。这是所有交易日志系统失败的头号原因，原方案完全未涉及。

字段分三层，Tier 1 自动、Tier 2 手填、Tier 3 延后。

#### Tier 1：自动回填（用户零输入）

| 字段 | 来源 | 说明 |
|---|---|---|
| `exec_id` | 自增 | |
| `decision_id` | 关联 `research_decision_log` | 可为 NULL（计划外交易，本身即信号） |
| `trade_date` | 输入日期 | |
| `code` / `name` / `sector` | `stock_daily` / `sector_daily` | |
| `direction` | BUY / SELL / ADD / REDUCE | A股只做多，无 short |
| `price` / `shares` / `amount` | 人填价与量，金额自动算 | |
| `regime_state` | `regime_history.risk_state` | 当日市场状态快照 |
| `regime_score` | `regime_history.risk_score` | |
| `risk_budget_equity` | `cio_decision_history` | 当日系统建议权益仓位 |
| `sector_rank_that_day` | `sector_daily` | 该股所属板块当日资金流排名 |
| `was_in_candidate` | 比对 `trade_journal` / Decision Log | **是否在事前候选池内**，核心字段 |

`was_in_candidate` 是整套设计里最重要的自动字段。它把「计划内交易」与「临时起意」自动区分开，无需人工判断，无法自欺。

#### Tier 2：人工必填（5 个字段，目标 60 秒）

| 字段 | 类型 | 说明 |
|---|---|---|
| `plan_source` | 枚举 | `system_candidate` / `own_research` / `intraday_impulse` / `external_tip` |
| `entry_reason` | 短文本（≤50字） | 为什么现在动手 |
| `planned_exit` | 文本 | 事前写好的止损位或减仓条件，允许填「未设」 |
| `deviation_note` | 短文本，可空 | 与计划不同的地方 |
| `conviction` | 1-5 整数 | 下单当下的确信度，用于后续校准 |

`conviction` 保留的理由与情绪自评不同：它是**可证伪的**。事后可以拿它跟实际结果做校准曲线（说 5 分的是不是真的赢面更高）。情绪评分无法证伪。

#### Tier 3：延后字段（样本达标后再启用）

`exit_price` / `holding_days` / `pnl_pct` / `pnl_amount` / `mistake_tag` / `max_adverse_excursion`

这些依赖平仓才有值，且归因需要样本量。v0.1 只留列不强制填。

### 3.4 双市场设计：`market_type` 分区，而非砍字段

**本节为 v0.1 修订。** 初稿基于「用户只做 A股」的假设建议砍掉外汇字段，该假设错误。用户同时在 MT5 交易外汇/期货，原方案的 XAUUSD / long-short / R_multiple 对应的是真实场景。

正确做法是加一个分区键 `market_type ∈ {ASHARE, MT5}`，字段按市场条件适用，而非一刀切删除。

| 字段 | ASHARE | MT5 | 说明 |
|---|---|---|---|
| `direction` | BUY / SELL / ADD / REDUCE | LONG / SHORT | A股个人实务单边做多，MT5 双向 |
| `stop_loss` / `take_profit` | 合并为 `planned_exit` 文本，允许「未设」 | **数值必填** | MT5 可从平台直接读取，A股靠看图，硬填价位会产生假数据 |
| `R_multiple` | 不适用 | **核心指标** | R 值依赖严格预设止损，MT5 具备，A股 T+1 无夜盘导致止损常延至次日开盘，R 值失真 |
| 持仓时长 | `holding_days` | `holding_minutes` | T+1 下最短持仓 1 天，分钟粒度无意义；MT5 需要分钟级 |
| `was_in_candidate` | 自动比对研投系统候选池 | 恒为 NULL | 研投系统不覆盖外汇，无候选池可比 |
| `regime_state` / `sector_rank` | 自动回填 | 不适用 | A股独有 |
| 宏观环境 | 复用 `regime_history` | 需另接（美元指数、Fed 预期） | 见下方说明 |
| `setup_type` | 降级为可选 | 建议启用 | A股受「候选只圈不筛、图形人工判断」红线约束；MT5 无此约束 |
| `emotion_before` / `emotion_after` | 删除 | 删除 | 两侧都删，见 §4.3 |

**两侧成熟度会长期不对称，这是特性不是缺陷：**

| | ASHARE | MT5 |
|---|---|---|
| 真实成交样本 | 0，从今天开始积累 | 可批量导入历史 |
| 客观字段质量 | 需手工录入价与量 | 平台导出，完全客观 |
| 主观字段（计划、理由） | 从记录之日起有 | **历史部分永久缺失** |
| 预计解锁层级 | L1（数月后） | L2 甚至 L3（导入后即可） |

MT5 历史导入有一个无法回避的限制：**导出的只有成交事实，没有当时的计划与理由**。所以 MT5 历史数据只能支撑「结果类分析」（胜率、期望值、盈亏比、持仓时长分布、按品种/时段/方向拆分、回撤），支撑不了本模块的核心指标 Plan-Execution Gap，因为「计划」这一半事后无法补录，回忆出来的计划是假的。

这个区分必须在报告里显式标注，不能混为一谈：

- MT5 历史部分：`data_completeness = outcome_only`
- 从记录之日起的双侧数据：`data_completeness = full`

**关于 `dollar_trend` / `fed_expectation`**：A股侧删除（已有 `regime_history` 覆盖，不重复造字段）；MT5 侧确实需要，但属于新数据源接入，与「三验收前不接全球资产」的铁律相关。建议 v0.1 先留列为 NULL，等全球资产接入时一并解决。

## 4. 指标体系

### 4.1 核心指标：Plan-Execution Gap（计划执行差）

**这是本 PRD 相对原方案最重要的补充。**

盈亏受市场噪声污染，单笔盈亏几乎不含个人能力信息，需要几十上百笔才能去噪。但「计划执行差」**单笔就有信息量，不需要样本量**。

四个可立即计算的比率：

| 指标 | 公式 | 起效样本 |
|---|---|---|
| **执行率** | `executed / (executed + missed)` | 5 笔 |
| **计划内比例** | `was_in_candidate=1 / 全部交易` | 5 笔 |
| **冲动交易占比** | `plan_source='intraday_impulse' / 全部` | 5 笔 |
| **止损预设率** | `planned_exit≠'未设' / 全部` | 5 笔 |

这四个指标在 v0.1 首月就能出数，且不需要任何 AI。它们是整个模块的地基。

### 4.2 二阶指标（需 ≥20 笔）

| 指标 | 说明 |
|---|---|
| 信心校准曲线 | conviction 1-5 分别对应的实际胜率，检验「你说得准不准」 |
| 计划内 vs 计划外收益差 | 直接检验「守纪律是否真的有钱赚」，这是纪律的唯一硬证据 |
| 卖出偏离度 | 实际卖出价 vs `planned_exit` 的距离分布 |
| 板块一致性 | 交易标的所属板块，是否落在当日系统圈定的主线板块内 |

### 4.3 为什么删掉情绪自评

原方案设 `emotion_before` / `emotion_after` / `confidence_score`。三点问题：

1. **事后自评有系统性偏差**。赚钱了倾向回忆成「当时很冷静」，亏钱了回忆成「当时冲动」。这是结果偏差污染过程记录。
2. **不可证伪**。情绪评分无法与任何客观事实核对，填错了没人知道，数据质量无法审计。
3. **增加填写摩擦**。属于「填了也用不上」的字段，直接推高单笔耗时。

**替代方案：可观察的行为代理变量。** 情绪不直接测，测它的行为痕迹：

| 代理变量 | 可自动/半自动获取 | 反映 |
|---|---|---|
| `plan_source='intraday_impulse'` | 手填 1 次点击 | 冲动 |
| `was_in_candidate=0` | 自动比对 | 脱离计划 |
| `planned_exit='未设'` | 手填 | 风险意识缺席 |
| 同日交易笔数 | 自动统计 | 过度交易 |
| 前 3 笔盈亏 vs 本笔金额 | 自动计算 | 连胜后加仓 / 连亏后报复 |

最后一项尤其关键：原方案要靠「连续盈利 3 次后亏损概率 +35%」这类统计结论来提醒，那需要数百笔样本。但换成「记录每笔金额与前 3 笔结果的关系」，**第 10 笔就能看出金额是否随连胜膨胀**，且是描述事实而非统计推断。

## 5. AI 分析层：按样本量分阶段解锁

原方案一次性给出 4 个 Agent。按当前 0 条真实交易，Agent 2/3/4 全部无法运行。改为**样本闸门制**，与用户既有治理纪律一致（拒绝伪精确、诚实 NULL）。

**闸门按市场独立计数。** MT5 侧因可导入历史，可能一开始就跨过 L2 门槛；A股侧从 0 起步。禁止把两侧样本合并计数来凑门槛，两个市场的行为规律不可通约（T+1 单边做多 与 24 小时双向杠杆是不同的行为环境）。

| 阶段 | 解锁门槛 | 能力 | 输出性质 |
|---|---|---|---|
| **L0 记录** | 立即 | 无 AI，仅 CLI 录入 + 四个比率 | 描述统计 |
| **L1 审计员** | ≥10 笔 | 对照计划与执行，列出偏离清单 | **描述，不归因** |
| **L2 校准员** | ≥30 笔 且 ≥2 个月 且 含≥2 种 regime | 信心校准、计划内外收益差 | 弱归因，带置信度 |
| **L3 模式识别** | ≥60 笔 且 ≥4 个月 且 含上涨/震荡/下跌 | 重复错误模式、个人交易画像 | 归因，需标 validation_status |
| **L4 规则进化** | ≥100 笔 且 L3 结论经过一轮前瞻验证 | 规则提炼与沉淀 | 可写入知识库 |

**闸门是硬约束。** 未达门槛时，对应 Agent 直接拒绝输出，返回「样本不足：当前 N 笔，需 M 笔」，不做降级输出。这条纪律的必要性在于：一份看起来很像样的错误归因报告，比没有报告危害更大，它会让你对着噪声调整交易方式。

### 5.1 L1 审计员输出样例（≥10 笔时）

```
执行审计 · 2026-09 第 1 周

系统信号 12 条
  已执行   3
  错过     7   ← 执行率 30%
  主动否决 2

计划外交易 2 笔
  600XXX  盘中临时买入，未在当日候选池
  002XXX  盘中临时买入，未在当日候选池

止损预设 1/5 笔（20%）

【描述，非结论】
本周执行率 30%，样本 12 条，不足以判断是否为稳定模式。
计划外交易 2 笔均发生在周三，当日市场 regime=Risk On。
```

注意措辞：全部是事实陈述，无一句因果归因。这是 L1 的定义。

### 5.2 Prompt 体系原则

三条约束写进所有 Coach Agent 的 system prompt：

1. **禁止在样本不足时使用因果语言**。禁用词：「因为」「导致」「说明你」。只允许「记录显示」「本期数据为」。
2. **每个结论必须附样本量与覆盖期**。格式：`结论（n=23，2026-08~10，含 Risk On/Neutral 两种状态）`。
3. **禁止给出交易建议**。检测到输出含具体标的代码 + 买卖动作时，直接拦截。

## 6. 报告模板

### 6.1 周报（自动生成草稿，人工回填 2 个字段）

沿用你已验证成功的模式（`build_weekly_intel.py` 的「自动量化 + 人工 3 字段」）。

```
Trading Coach 周报 · {date_range}
```

## 7. TIP：Trader Intelligence Protocol

原方案提议对标 AIP 建 TIP。方向认可，但**不应照抄 AIP 六元组**，交易者的可测维度与资产不同。

AIP：`state / score / trend / driver / risk / confidence`

TIP 建议五元组：

| 字段 | 含义 | 起效样本 |
|---|---|---|
| `sample_confidence` | **必须排第一**。样本量决定的整体可信度，<20 笔时后四项一律标 UNVALIDATED | 0 |
| `discipline` | 纪律执行率（执行率 + 止损预设率合成） | 10 |
| `consistency` | 计划一致性（计划内交易占比） | 10 |
| `calibration` | 信心校准（conviction 与实际胜率的拟合度） | 30 |
| `risk_behavior` | 风险行为（仓位是否随连胜膨胀、连亏后是否报复） | 30 |

把 `sample_confidence` 放第一位是刻意设计。AIP 的教训是 score 与 confidence 容易被混用（记忆库已记录「score≠confidence」这条红线），TIP 从结构上强制先看置信度。

## 8. 与既有优先级铁律的关系

用户 2026-08-04 已定铁律：`1.9A✅ → 1.9C✅ → 1.9B✅ → 月报v0.2 → 全球资产接入 → 日报优化`，且「三验收前不接全球资产」。

Trading Coach 是否插队？**拆成两半处理，这是唯一能与铁律共存的方式：**

| 部分 | 排期 | 理由 |
|---|---|---|
| **采集层（Phase 0 + Tier 1/2）** | **立即启动，不排队** | 样本量是时间的函数。晚一个月开始，就永久少一个月数据，且无法补录（事后回忆的计划是假的）。这是全系统里唯一受时间惩罚的模块 |
| **分析层（L1 及以上）** | 排在铁律之后 | 纯算法工作，不受时间惩罚，随时可做。且没有样本时做了也跑不动 |

这个拆分不违反 8 周冻结纪律。冻结的范围是「日报信息生产扩张 + Layer1 评分模型」，Coach 采集层既不产日报信息，也不碰任何评分模型。它属于纯记录层。

## 9. Roadmap

分两条线并行，互不阻塞。

**A 线：A股侧（从 0 积累，受时间惩罚，立即启动）**

| 阶段 | 内容 | 工作量 | 前置 |
|---|---|---|---|
| **A0** | `exec_result` 三态化；补卖出记录路径；每日收盘后 2 分钟标记 | 半天 | 无 |
| **A1** | 建 `trade_execution` 表（含 `market_type`）；CLI 录入（≤90 秒/笔）；Tier 1 自动回填 | 1-2 天 | A0 |
| **A2** | 四个核心比率 + 周报草稿 | 1 天 | ≥10 笔 |
| **A3** | L1 审计员 | 1 天 | ≥10 笔 |
| **A4** | L2 校准员 + TIP 前三元组 | 2 天 | ≥30 笔，≥2 月 |

**B 线：MT5 侧（历史可导入，不受时间惩罚，但价值兑现最快）**

| 阶段 | 内容 | 工作量 | 前置 |
|---|---|---|---|
| **B0** | 你在本机跑 `mt5_export.py` 导出 deals/orders CSV | 10 分钟 | 需你操作 |
| **B1** | 导入器：CSV → `trade_execution`（`market_type=MT5`，`data_completeness=outcome_only`） | 1 天 | B0 |
| **B2** | 结果类分析：胜率 / 期望值 / 盈亏比 / R 分布 / 持仓时长 / 按品种·时段·方向拆分 / 回撤 | 1-2 天 | B1，样本量视导出结果 |
| **B3** | 从 B2 结论反推 A股侧应重点观测的行为维度 | 半天 | B2 |

**B 线优先级高于 A2 及以后。** 理由：B0 只要 10 分钟就能知道历史样本到底有多少笔，而这个数字直接决定 §11 问题 1 的答案，进而决定整个模块的能力上限。在样本量未知的情况下继续设计分析层，是在猜。

**B3 是双线的真正结合点**：MT5 历史能告诉你「你这个人在有杠杆、可双向、24 小时的环境里，错误集中在哪」。这些结论不能直接搬到 A股，但能指出 A股侧该优先记录哪些字段，避免 A股侧从零盲目积累。

按当前 A股信号频率（7 个交易日 121 条信号），若执行率维持 30%，A2/A3 的 10 笔门槛约需 3-5 周。

## 10. 风险与诚实缺口

| 风险 | 说明 | 缓解 |
|---|---|---|
| **霍桑效应** | 开始记录本身会改变行为，前 20 笔不是真实基线 | 前 20 笔打 `baseline_contaminated=1` 标记，L2 以上分析时排除或单独分组 |
| **记录中断** | 交易日志的主要死因。若单笔 >90 秒，3 周内必停 | 硬性砍字段；Tier 1 全自动；每日一次批量标记而非逐笔实时 |
| **样本永远不够** | 若实际交易频率很低（如月均 2-3 笔），L3 门槛需 2 年以上 | 见 §11 问题 1，若频率过低应把 Coach 降级为纯记录层，永不上 AI 分析 |
| **测量对象污染** | Coach 若接入 CIO，测量的就不再是人 | §2.2 硬边界，前 100 笔不接 |
| **自欺** | 手填字段可以撒谎 | 核心判定字段 `was_in_candidate` 走自动比对，人无法篡改 |

## 11. 开放问题（需用户拍板后才能进实现）

1. **MT5 历史成交有多少笔、跨多长时间？**（最高优先级，其他三问都依赖它）跑一次 `mt5_export.py` 即可知道。这个数字决定 B 线能直接跳到哪一层，也校准 §11 问题 2 的答案。在此之前所有关于分析层的排期都是估算。
2. **A股实际交易频率是多少？** 月均笔数决定 A 线可行性上限。若月均 <3 笔，A股侧的 L3/L4 应直接砍掉，A股 Coach 永久停在记录层，重心放 MT5 侧。
3. **两个市场哪个是主要痛点？** 你的直觉判断即可。这决定资源投向。我的先验猜测是 MT5（杠杆 + 双向 + 24 小时，执行纪律压力远大于 T+1 的 A股），但这只是推测，可信度 60%，需要你确认或推翻。
4. **A股券商对账单能否导出？** 若能，A股侧也可获得 Tier 1 历史（价格、日期、标的客观可靠），主观字段留空。这能把 A 线的 L2 门槛提前数月。
5. **每日记录时间预算？** 若能接受收盘后固定 5 分钟批量处理，设计可以更完整；若只能接受 1 分钟，Tier 2 需再砍到 3 个字段。

## 12. 本 PRD 对原方案的修订清单

| # | 原方案 | 本 PRD | 理由 |
|---|---|---|---|
| 1 | 新建 `trade_journal` | 改造既有表 + 新增 `trade_execution` | 表已存在，且用户已定「Trade Log 从 Decision Log 继承」 |
| 2 | 外汇字段一套走天下 | `market_type` 分区，两市场字段条件适用 | 用户双市场交易，A股 T+1 单边做多，MT5 双向有杠杆，字段不可共用也不可互删 |
| 3 | `emotion_before/after` | 行为代理变量 | 事后自评不可证伪且有结果偏差 |
| 4 | 4 个 Agent 一次上 | 样本闸门分 5 级解锁 | 当前真实交易 0 条 |
| 5 | Coach 接入 CIO 层 | 前 100 笔禁止接入 | 方案内部自相矛盾 + 反馈环污染 |
| 6 | 核心指标为盈亏归因 | 核心指标为 Plan-Execution Gap | Gap 单笔即有信息量，盈亏需大样本去噪 |
| 7 | 未提记录负担 | 90 秒硬约束 | 记录中断是此类系统头号死因 |
| 8 | TIP 对标 AIP 六元组 | TIP 五元组，`sample_confidence` 置首 | 交易者可测维度不同；防 score/confidence 混用 |
